## 🏭 Factory Builder Pattern

### What is it?

The Factory Builder Pattern provides a consistent way to seed test data directly into the database using TypeORM repositories. This is more efficient than creating data through API endpoints.

### Benefits

✅ **Performance**: Direct database insertion is faster than HTTP requests  
✅ **Consistency**: Centralized data creation logic  
✅ **Batch Operations**: Create multiple entities in one transaction  
✅ **Type Safety**: TypeScript interfaces ensure valid data  
✅ **Reusability**: Share factories across multiple test files  

## 📝 Usage Examples

### Basic Usage - Single Asset

```typescript
import { AssetFactory, createAssetEntity } from '../factories/asset.factory';
import { runFactories } from '../../factories/builder.factory';

// Create asset entity data
const assetEntity = createAssetEntity({
  path: 'uploads/test-image.jpg',
  size: 1024000,
  initialName: 'test-image.jpg',
});

// Create factory and run
const factory = new AssetFactory([assetEntity]);
const [createdAsset] = await runFactories(factory);

console.log(createdAsset.id); // UUID generated by database
```

### Batch Creation - Multiple Assets

```typescript
// Create multiple assets at once
const assetsToSeed = [
  createAssetEntity({ path: 'image1.jpg', size: 1024000 }),
  createAssetEntity({ path: 'image2.png', size: 2048000 }),
  createAssetEntity({ path: 'document.pdf', size: 512000 }),
];

const factory = new AssetFactory(assetsToSeed);
const createdAssets = await runFactories(factory);

console.log(`Created ${createdAssets.length} assets`);
```

### In Test Setup (beforeAll)

```typescript
describe('My Asset Tests', () => {
  let app: INestApplication;
  let testAsset: Asset;

  beforeAll(async () => {
    // ... initialize app

    // Seed test data using factory
    const assetEntity = createAssetEntity({
      path: 'uploads/test-asset.jpg',
      size: 1536000,
    });

    const factory = new AssetFactory([assetEntity]);
    const [createdAsset] = await runFactories(factory);
    
    testAsset = createdAsset;
  });

  it('should retrieve seeded asset', async () => {
    const res = await request(app.getHttpServer())
      .get(`/assets/${testAsset.id}`)
      .expect(200);

    expect(res.body.path).toBe('uploads/test-asset.jpg');
  });
});
```

## 🔧 Helper Functions

### `createAssetEntity(options?)`

Creates a Partial<Asset> object for database seeding.

```typescript
const asset = createAssetEntity({
  path: 'uploads/custom.jpg',    // Optional
  size: 2048000,                  // Optional
  initialName: 'custom.jpg',      // Optional
});
```

**Default Values:**
- `path`: `uploads/test-asset-{timestamp}.jpg`
- `size`: `1024000`
- `initialName`: `test-file-{timestamp}.jpg`

### `createAssetPayload(options?)`

Creates a payload object for API requests (POST /assets).

```typescript
const payload = createAssetPayload({
  path: 'uploads/api-test.jpg',
  size: 1536000,
  initialName: 'api-test.jpg',
});

await request(app.getHttpServer())
  .post('/assets')
  .send(payload);
```

### Other Helpers

- `createMinimalAssetPayload()` - Only required fields
- `createLargeAssetPayload()` - 10MB file size
- `createAssetWithExtension(ext)` - Specific file extension

## 🎯 When to Use Factory vs API

### Use Factory Builder (Database Seeding) When:

✅ Creating test data in `beforeAll` hooks  
✅ Need to seed multiple entities efficiently  
✅ Setting up complex test scenarios  
✅ Performance is important  
✅ Testing GET/DELETE operations  

```typescript
// ✅ Good - Use factory for setup
beforeAll(async () => {
  const factory = new AssetFactory([createAssetEntity()]);
  const [asset] = await runFactories(factory);
  testAssetId = asset.id;
});
```

### Use API Requests When:

✅ Testing the CREATE endpoint itself  
✅ Testing validation logic  
✅ Testing the full request-response cycle  
✅ Need to verify HTTP status codes  

```typescript
// ✅ Good - Test the POST endpoint
it('should create asset via API', async () => {
  const payload = createAssetPayload();
  
  const res = await request(app.getHttpServer())
    .post('/assets')
    .send(payload)
    .expect(201);
});
```

## 🧹 Cleanup Best Practices

Always clean up seeded data in `afterAll`:

```typescript
afterAll(async () => {
  // Clean up seeded assets
  for (const asset of seededAssets) {
    try {
      await request(app.getHttpServer())
        .delete(`/assets/${asset.id}`);
    } catch (error) {
      console.warn(`Failed to delete asset ${asset.id}:`, error);
    }
  }

  await app.close();
});
```

## 💡 Tips

1. **Use unique identifiers**: Factory helpers include timestamps to prevent conflicts
2. **Batch when possible**: Create multiple entities in one factory call
3. **Clean up always**: Use try-catch in afterAll to ensure cleanup
4. **Log output**: Factory logs help debug seeding issues
5. **Type safety**: Use TypeScript interfaces for compile-time validation

---

**Remember**: Factory seeding is for test setup. Always test the actual API endpoints separately!
